# 知源 · 个人 RAG 知识助手

**上传自己的文档，选择知识库提问，通过引用核对原文。**

知源是一款支持自定义知识库的文档问答工具，基于 DocsGPT 二次开发。你可以使用笔记、产品手册或项目资料建立知识库；AI 开发文档只是一个可选主题，不限制上传其他资料。添加文档不需要重新训练大模型。

这是需要自行部署的源码版。先阅读 **[安装与首次使用指南](GETTING_STARTED.md)**，配置自己的数据库和模型服务，再开始使用。

首次部署使用指南中的源码启动流程。根目录旧 `setup.ps1` / `setup.sh` 默认安装上游镜像，可能显示原版 DocsGPT 界面。

[安装与首次使用](GETTING_STARTED.md) · [下载最新源码 ZIP](https://github.com/a1958749/zhiyuan-rag/archive/refs/heads/main.zip) · [反馈问题](https://github.com/a1958749/zhiyuan-rag/issues)

## 可以做什么

| 功能 | 使用方式 |
|---|---|
| 上传原始文档 | 支持 TXT、Markdown、PDF、DOCX 等格式，无需提前手动切分 |
| 自动建立知识库 | 系统解析文档、分块、生成 embedding 并建立检索索引 |
| 选择知识来源 | 在聊天输入框旁选择已经处理完成的知识库，再围绕对应资料提问 |
| 查看回答引用 | 打开答案来源，核对原文是否支持结论 |
| 配置分块 | 在知识库的来源设置中选择分块策略和参数；修改后重新索引 |
| 切换中英文 | 默认简体中文，在“设置 → 常规设置 → 语言”选择 English |
| 查看固定帮助 | 首页和帮助菜单提供使用指南与示例 TXT；产品介绍和使用说明无需 AI 生成 |

原生上传、聊天和基础引用能力来自 DocsGPT。本项目增加了知源的产品界面、固定中英文引导，以及技术文档检索和快照引用适配。自定义上传使用原生知识库流程；额外的混合检索、重排、有限复检与证据门控需要相应索引和独立服务配置，不会自动应用到每个新文件。

## 四步开始使用

1. **上传文档**：在首页点击“管理 / 上传知识库”，或进入“设置 → 知识库”。第一次建议使用 [示例 TXT](frontend/public/examples/zhiyuan-first-document.txt)。
2. **等待入库完成**：等到来源显示处理完成或可用。上传成功通知不等于已经建立好索引。
3. **选择知识库**：回到聊天页，通过输入框旁的来源选择器选中刚上传的资料。
4. **提问并核对引用**：例如“星河项目由谁负责演示，什么时候开始？请引用原文。”示例文档应支持“小林”“周五下午三点”；打开引用核对。

更换知识主题时，新建来源并上传相应资料即可。更新文档或调整分块参数后，需要重新入库或索引。

## 从源码安装

需要 **Python 3.12、Node.js 22、uv，以及 PostgreSQL / Redis**。可以使用 Docker 启动数据库服务。

```bash
git clone https://github.com/a1958749/zhiyuan-rag.git
cd zhiyuan-rag
```

然后按 [GETTING_STARTED.md](GETTING_STARTED.md) 完成依赖安装、后端 `.env`、前端 `frontend/.env.local` 和启动配置。

Windows 使用三个终端分别启动 API / worker、前端和调度器。前端默认地址为 `http://localhost:5173`，后端默认地址为 `http://localhost:7091`。

源码不包含你的模型密钥、数据库、预建索引或模型权重。不要提交 `.env`、`.secrets` 或上传资料中的敏感内容。

## 与原版相比的改进

增加固定中英文使用引导、快照证据核验和独立混合检索流程。自定义上传继续使用原生知识库；高级检索需要单独配置。



对比的是本项目采用的 DocsGPT 固定版本。原版已有文档上传、会话、来源引用、多语言与 Agent / 工具能力；部分检索后端也支持 Hybrid / RRF。知源的改进如下：

| 方面 | 原版已有能力 | 知源的新增改进 | 对使用者的价值 |
|---|---|---|---|
| 首次使用 | 帮助菜单和上游文档入口 | 首页四步引导、独立使用指南、可下载示例 TXT 和核验问题 | 更容易完成上传、入库、选来源、查引用的完整流程 |
| 产品介绍与帮助 | 通用聊天和帮助入口 | “知源是什么”“知源怎么使用”等独立问题直接返回固定中英文说明 | 无需模型猜测使用方法，也不需要为帮助内容调用模型 |
| 语言体验 | 多语言支持与浏览器语言检测，英语作为回退语言 | 默认简体中文，提供明确的 English 切换并保存选择 | 首次打开即可按中文说明操作，仍可使用英文界面 |
| 技术文档检索 | 检索方式随向量后端和配置变化 | 独立 Dense + BM25 + RRF 流程，同时匹配语义与 API / 参数关键词 | 固定技术资料中的必要信息更容易进入前部结果；提升数字见下方 |
| 技术资料引用 | 已有来源引用 | 绑定稳定证据 ID 与保存的文档 / 源码快照，校验回答引用和本次证据是否对应 | 能核对回答实际使用的历史原文，避免外链更新后出现内容错位 |
| 复杂问题处理 | 通用 Agent / 工具能力 | 可选重排、最多两条子查询和一轮复检，保留原问题及关键标识符，失败回退首轮证据 | 处理复合问题时控制调用范围；这些组件需要单独配置，不是默认全部开启 |


在 **FreshStack LangChain 2024-10 固定资料、150 题本地留出集**上，共用 Qwen3-Embedding-0.6B。下表统一比较受控 Dense 基线（B0）与知源 Hybrid（H0）：

| 指标 | 受控 Dense（B0） | 知源 Hybrid（H0） | 增量 |
|---|---:|---:|---:|
| Coverage@5：前 5 项覆盖的所需信息比例 | 38.51% | **45.99%** | **+7.48 个百分点** |
| Coverage@10：前 10 项覆盖的所需信息比例 | 49.06% | **57.64%** | **+8.59 个百分点** |
| α-nDCG@10：前部结果的信息覆盖与排序质量 | 0.2671 | **0.3254** | **+0.0583** |
| Recall@50：前 50 项找回的标注相关片段比例 | 35.76% | **40.58%** | **+4.82 个百分点** |
| Precision@10：前 10 项中标注相关片段的占比 | 15.20% | **17.93%** | **+2.73 个百分点** |
| MRR：第一条相关结果的排名评分，越高越好 | 0.3773 | **0.4758** | **+0.0986** |
| nDCG@10：前 10 项相关结果的排序质量 | 0.2111 | **0.2522** | **+0.0412** |

这些结果说明：Hybrid 找回了更多相关资料，前排结果更相关，所需信息覆盖也更完整。Coverage 按每题的必要信息点计算后取平均，不是正确回答问题的比例；MRR、nDCG 与 α-nDCG 是评分，不是准确率百分比。各项数字是**同一次 Hybrid 改动的不同观察角度**，不是七项独立功能优化。

Coverage@10 增量的 95% 配对 bootstrap 区间为 **[+3.16, +13.53] 个百分点**。另测的原生 ClassicRAG（U）共用了 Qwen embedding，其 Coverage@10 和 α-nDCG@10 与表中的 B0 一致，**不是原版默认 Granite 模型配置**；因此这些数字不代表对原版所有配置的全面提升。区间采用配对 bootstrap，属于探索性比较，未做多重比较校正。

这项收益适用于固定技术文档检索，**不是回答准确率提升，也不能直接推广到任意新上传文件**。在固定上下文预算下，进入模型的证据覆盖增量只有 0.78 个百分点，区间跨零，尚未证明回答质量、速度或费用同步改善。日常上传自己的文件仍走原生知识库流程。

## 使用时注意

- 模型回答可能出错，引用也需要核对，不能仅凭有引用就认为答案正确。
- 使用云端模型时，问题和检索到的文档片段会发送给配置的模型服务；远程 embedding 也会发送文本。本地保存文档不代表所有处理均离线。
- 扫描 PDF 的 OCR 能力取决于解析器和部署配置；首次使用建议先验证小型 TXT 或 Markdown 文件。
- 知识库只能回答资料中有依据的信息。历史技术文档不代表当前最新版产品行为。
- 当前版本不会自动执行回答中的命令。

## 常见问题

| 问题 | 检查方式 |
|---|---|
| 上传后答不出来 | 是否已完成入库、是否选择正确来源、原文是否包含答案 |
| 页面连接失败 | 前端两个 API 地址是否指向实际后端、修改配置后是否重启前端 |
| 文档处理失败 | worker 是否运行、内部密钥是否一致、文件是否能提取文字 |
| 模型连接失败 | 自己的 API 地址、模型名、密钥、额度和服务状态 |
| 想换成自己的资料 | 上传新的来源，并在聊天中选择它，无需训练大模型 |
